Simple troubleshooting

Use this compact guide when something does not look right on the dashboard or when support evidence is needed.

TDC-XPhotoelectric sensor

Simple troubleshooting guide

Symptom What it usually means Recommended action
Operations page does not open The Node-RED service or network path may be unavailable. Check the TDC-X IP address, browser URL and network connection. If other pages also fail, contact support.
Line shows OFFLINE The gateway cannot read the WISE device. Check power, network/Wi-Fi, device IP reachability and field wiring. If the problem continues, export logs and contact support.
Count does not increase The sensor is not detecting items or the WISE counter is not receiving pulses. Check object path, sensor indication, WISE device status and confirm the correct line is being observed.
Update queue keeps increasing The gateway cannot send updates to the server right now. Check server connectivity. The system continues storing retries automatically. If the queue does not reduce after connectivity is restored, contact support.
Local snapshots keep increasing Pending records may not be available or the server may be temporarily unavailable. Check server status and review the system log for related warnings.
Transitioning remains active for a long time The system is waiting to complete a session change or counter reset. Wait briefly, then review the system log. If the state does not clear, capture screenshots and export the CSV files for support.
Many repeated WARN or ERROR logs There is a repeated communication or process issue. Open the System log page, download the CSV and share it with SICK support.

Good operator practice

  • Check the Operations page first, then the System log page.
  • Export CSV files before rebooting or making changes when support evidence is needed.
  • Avoid changing field hardware settings during normal operation.
  • If a line is actively switching session, avoid interrupting the system unless instructed by support.
Reminder: temporary network or server interruptions do not immediately mean lost data. The system uses a durable retry queue to resend failed updates automatically.
